# AI Contributor Guide

This repository is designed for small, verifiable AI-assisted changes. Read this file before editing, then read the local docs linked from the task.

## First Pass

- Start with `ARCHITECTURE.md` for the pipeline model.
- Use `ARCHITECTURE_EVOLUTION.md` for structural work and sequencing.
- Check `git status --short` before editing. The tree is often dirty with generated screenshots and reports; do not revert unrelated changes.

## Package Map

- `packages/plugin`: Vite plugin, Babel transform, artifact virtual modules, codegen, Node extractor harness, vendored three.js extractor files.
- `packages/runtime`: browser/runtime helpers, `PrecompiledMaterial`, hydrator, slim bundle, auxiliary artifact loading, slim-support helpers.
- `packages/contract`: shared extractor/codegen/runtime contract. Put cross-package vocabulary here first.
- `packages/examples/batch`: visual capture/replay harness and coverage reporting. Keep harness-only behavior out of runtime unless it is truly test scaffolding.
- `packages/inspector-panel`: inspector UI integration.
- `packages/site`: docs/site build.

## Change Rules

- Prefer shared contract updates over duplicated lists. `source.kind`, texture-property lists, graph normalization, and artifact validation belong in `@tsl-precompile/contract`.
- If you add or rename a `source.kind`, update `packages/contract/src/kinds.js`, the extractor/codegen/runtime handling, and the drift/contract tests in the same change.
- If you touch `packages/plugin/src/vendor/*` or `packages/plugin/src/three-rewrite.js`, run rewrite/coverage tests and document vendor assumptions in `packages/plugin/src/vendor/VENDORING.md` when provenance changes.
- If you touch `emit-updater.js`, keep generated modules parseable and run the updater tests.
- If you touch `hydrator.js`, prefer extracting a named helper/module over adding another broad fallback branch.
- If behavior currently lives in `packages/examples/batch/run-e2e.mjs` but real users need it, move it toward `packages/runtime/src/slim-support/*`.

## Test Tiers

- Small code changes: `pnpm test`.
- Extractor/artifact-generation changes: `pnpm test:generation` while iterating.
- Release or broad cross-package changes: `pnpm test:full` once before handoff; do not run it after every edit.
- Codegen/kind/extractor changes: `pnpm test:coverage`.
- Artifact/manifest changes: `pnpm verify`.
- Slim-bundle or three.js rewrite changes: `pnpm --filter @tsl-precompile/runtime build:slim`.
- Visual-runtime changes: use `pnpm test:e2e:tier1` for the configured PR-sized visual gate.

## Generated Outputs

- `packages/examples/batch/results/**` and `packages/examples/batch/results/shots/**` are generated by visual runs. Do not hand-edit them.
- Only update generated coverage reports/screenshots when the task explicitly refreshes visual evidence.
- Keep source changes and generated evidence easy to review. If a visual run produces broad noise, call it out in the final summary.

## Parallel Work

- Multiple agents may be running in isolated worktrees under `.claude/worktrees/`. They share this repo's object database, so any history change in one tree is visible to all of them.
- In isolated worktrees, verify the worktree base before editing. Stop if it is stale.
- **Do not rewrite commits.** No `git commit --amend`, `git reset --soft|--mixed|--hard <ref>` against existing commits, `git rebase`, `git push --force`, or `git push --force-with-lease`. If a commit needs to change, create a new commit on top.
- **Do not move HEAD off the assigned branch.** No `git checkout <commit-or-branch>`, `git switch <branch>`, or `git reset --hard <other-rev>` to "test" a different revision. Each worktree must stay on the branch it was created with. To compare against another revision, use `git show`, `git diff <ref>`, or `git worktree add` for a new throwaway tree.
- **Do not move stashes across branches or worktrees.** Prefer a scratch commit on the current branch over `git stash`. If you must stash, pop it in the same worktree on the same branch you stashed from — never in a sibling worktree.
- These rules apply to `Bash` commands you issue *and* to anything you delegate to subagents.

## Release Surface

- Public packages are `vite-plugin-tsl-precompile`, `@tsl-precompile/runtime`, and `@tsl-precompile/contract`.
- Keep package exports intentional. If a file is meant to be imported by users or the harness, expose it through `package.json`.
- Avoid adding new public API until the runtime/contract boundary is clear and tested.
