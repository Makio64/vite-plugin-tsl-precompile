Manual TSL setup4 steps

Tested with Vite >=6.4.3 <9. Start in compatibility mode. Enable slim: 'source' only after capture, build, and production preview pass.

  1. 1

    Install

    Pin three.js exactly. Artifacts are emitter-specific.

    pnpm add -D vite-plugin-tsl-precompile@alpha
pnpm add @tsl-precompile/runtime@alpha three@0.185.1 --save-exact
# TypeScript only:
pnpm add -D @types/three@0.185.1 --save-exact
  2. 2

    Configure Vite

    vite.config.js

    Merge this into the existing config; preserve every current plugin and option. Keep slim off during adoption.

    import { defineConfig } from 'vite';
import tslPrecompile from 'vite-plugin-tsl-precompile';

export default defineConfig({
  plugins: [ tslPrecompile() ],
  build: { target: 'esnext' },
  optimizeDeps: {
    include: [ 'three', 'three/webgpu', 'three/tsl' ],
  },
});
  3. 3

    Register the renderer

    main.js

    Pass the app's existing live renderer—do not create a second one. Put setup after the app's one existing renderer.init(), or before it and await setup.ready only after that same init finishes.

    import { setupPrecompile } from '@tsl-precompile/runtime/setup';

// Keep the app's existing, single `await renderer.init()` above this.
const setup = setupPrecompile({ renderer });
await setup.ready;

    No marker is required for direct new *NodeMaterial(...) calls. Add material.precompile('hero-body') only as a stable-name override; use autoMark: false to opt out globally.

  4. 4

    Capture and prove it

    Commands show src; replace or repeat --source for the app's actual JavaScript/TypeScript roots. Never fabricate or edit artifact JSON.

    Terminal A · keep running

    pnpm dev

    Open the dev URL in a WebGPU browser and exercise every real route and state.

    Terminal B · after capture

    pnpm exec tsl-precompile-doctor --source src
pnpm exec tsl-precompile-verify --source src --source-root . artifacts
git add artifacts/
pnpm build

    Production proof · keep running

    pnpm preview

    Replay the same matrix in preview. Require WebGPU, nonblank changing pixels, and zero page, console, request, capture, or GPU validation errors. Record anything you could not reach.

Questions

What changes in production?

Compatibility mode validates artifacts but keeps three.js's live compiler authoritative. Slim mode replays captured WGSL with generated updates and no NodeBuilder. WebGPU still creates the pipeline and the driver still compiles WGSL to native code. See the boundary →

Why capture a real render?

Geometry, camera, lights, shadows, fog, clipping, and render targets can change the shader. A source scan cannot prove those runtime contexts.

Do I commit artifacts/?

Yes. They are generated build inputs, like a lockfile. Never fabricate or hand-edit them.

When do I recapture?

After a marked TSL graph, marker name, relevant render topology, three.js version, or artifact schema changes. Render the affected paths again, verify, commit, and rebuild.

When is slim mode safe?

After compatibility capture, non-zero artifact verification, build, and production preview all pass across every reachable render path.
