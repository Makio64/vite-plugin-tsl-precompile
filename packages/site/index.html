Automatic marking

  • Framework subresource-aware
  • Collision-checked owners
  • Recapture after constructor reorder
03production optimization

Slim runtime

Alias production Three.js to a node-builder-stripped bundle after the base capture workflow is green.

tslPrecompile({ slim: 'source' })
  • No runtime NodeBuilder
  • Loud uncovered-path errors
  • Lazy full-renderer fallback

working quickstart

One-time setup.
Then one line per material.

This new-project path uses guarded slim: 'source'. Existing apps can omit slim while they audit capture and fallback coverage.

01

Install

Plugin at build time, runtime in the app.

pnpm add -D vite-plugin-tsl-precompile
pnpm add @tsl-precompile/runtime
02

Configure Vite

Keep top-level await and Three's entries predictable.

import { defineConfig } from 'vite';
import tslPrecompile from 'vite-plugin-tsl-precompile';

export default defineConfig({
  plugins: [ tslPrecompile({ slim: 'source' }) ],
  build: { target: 'esnext' },
  optimizeDeps: {
    include: [ 'three', 'three/webgpu', 'three/tsl' ],
  },
});
03

Register the renderer, then mark a material

The marker captures only after that material participates in a real render.

import { WebGPURenderer, MeshStandardNodeMaterial, Mesh } from 'three/webgpu';
import { setupPrecompile } from '@tsl-precompile/runtime/setup';

const renderer = new WebGPURenderer();
const setup = setupPrecompile({ renderer });
await renderer.init();
await setup.ready;

const water = new MeshStandardNodeMaterial();
water.colorNode = waterGraph;
water.precompile('ocean-water');
scene.add( new Mesh( geometry, water ) );
04

Capture, commit, build

Visit every relevant route and state before shipping.

straight answers

Before you adopt it.

Does the browser still compile a shader?

Yes. WebGPU still creates the pipeline and the GPU driver compiles WGSL to native code. The plugin removes Three's JavaScript TSL graph walk and WGSL generation for captured materials.

Do users download the artifact JSON?

No. The JSON is build input. Vite turns it into tree-shakeable virtual modules containing shader source, metadata, and the generated updater.

Do I commit artifacts/?

Yes. Treat it like generated source or a lockfile. It makes local builds and CI consume the same shader inputs and lets code review see shader changes.

Is slim: 'source' required?

No. It is the preferred compiler-free profile for a fully covered new Vite app. Existing apps can start with normal capture; either slim mode requires every reachable path to be captured or handled by fallback.

Can I try it without editing every material?

Use autoMark: true. Generated names are stable per transformed module and framework subresource, but constructor order remains positional, so reordering can require recapture.

Does it support WebGLRenderer?

No. This pipeline targets Three.js WebGPURenderer and WGSL. Pin Three to an exact supported patch because the emitted shader contract follows renderer internals closely.
