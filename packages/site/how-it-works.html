the mental model

TSL is the authoring format.
The artifact is the deployment format.

A material starts as a live JavaScript graph. Development captures the shader contract for the scene where that material is used. Vite verifies and embeds it. Production reconnects the embedded shader to live values.

three layers, separate jobs

Move code generation earlier.
Keep scene values live.

Precompilation does not turn a material into a screenshot. It stores the stable program and a plan for reconnecting dynamic values.

01 / AUTHOR

Write normal TSL

Build material graphs with the same Three.js APIs. The marker is metadata for the build pipeline, not a new shader language.

the journey of one material

From water
to a production shader.

Each boundary has one owner. The browser supplies scene facts, the plugin owns persistence and rewriting, and the runtime owns hydration.

  1. 01
    SOURCE

    The marker declares intent

    water.precompile('ocean-water') gives the artifact a project-global name. With autoMark: true, the transform can add generated names instead.

    nameocean-water
  2. 02
    DEV BROWSER

    A real render supplies context

    The marker waits until the material is actually rendered. That identifies the owning object and scene topology before an isolated extraction produces the artifact variants.

    objectcameralightsMRT
  3. 03
    DEV SERVER

    The plugin persists generated source

    The capture endpoint validates the request, applies collision rules, writes an immutable content-addressed file, and updates the manifest.

    fileocean-water.<hash>.json
  4. 04
    VITE BUILD

    Validation runs before rewriting

    Content, call-site ownership, source revision, and exact Three/toolchain versions must agree. Then Babel replaces the marker with __applyPrecompiled and a virtual artifact import.

    gatevalidated ✓
  5. 05
    PRODUCTION

    The runtime hydrates, then WebGPU takes over

    The embedded shader receives live resources and generated value updates. WebGPU still creates the pipeline and the driver still compiles WGSL to native code.

    networkno artifact request

why capture waits for a render

A material alone is not a shader variant.

Three's generated program depends on where the material is rendered. Capturing only the constructor would miss facts that change WGSL, bindings, or render state.

Important

Direct live NodeBuilderState harvesting is a tested architecture direction, not the default shipped capture path yet. Today, real rendering selects context and an isolated compatibility pass performs extraction.

what precompilation handles

Stable program,
live inputs.

  • ✓
    Static shader source

    Captured WGSL is embedded in the production chunk.

  • ✓
    Resource reconstruction

    Bindings reconnect textures, samplers, lights, camera buffers, and other live resources.

  • ✓
    Generated updates

    Supported dynamic values are written through a generated plan instead of rebuilding the graph.

  • ✓
    Optional slim runtime

    Once every path is covered, slim: 'source' removes the runtime NodeBuilder and lets Vite tree-shake unused exports.

what WebGPU still handles

The GPU work
still happens.

  • →
    Pipeline creation

    The browser creates a pipeline for the supplied WGSL and render state.

  • →
    Driver compilation

    The GPU driver translates WGSL into hardware-native instructions.

  • →
    Resource uploads

    Textures, buffers, uniforms, and geometry still reach the GPU normally.

  • →
    Rendering

    Draw submission and GPU execution are unchanged.

a safe adoption order

Capture first.
Slim down last.

1

Prove one explicit material

Install the base pipeline, capture a representative PBR material, and inspect its generated artifact.

2

Expand observed coverage

Visit relevant routes and states. Use explicit names for control or autoMark for a broad trial.

3

Verify compatibility

Run the artifact checks and visual/runtime gates appropriate for your scene before changing the renderer bundle.

4

Enable slim: 'source'

Remove the NodeBuilder only when every reachable material path is captured or covered by the lazy full-renderer fallback.
